# M4 增量索引最终验收记录

## 验收范围

本记录覆盖 M4.0–M4.4：变化判定、文件事件来源、事件归并与增量写入、后台监听生命周期，
以及关闭和重启后的恢复。

## 验收检查

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 创建文件后可建立元数据、正文和 FTS 记录 | 通过 | 核心增量索引临时目录测试 |
| 修改文件后正文和搜索内容更新 | 通过 | 核心增量更新测试与重启后更新测试 |
| 删除文件后元数据、正文和 FTS 记录移除 | 通过 | 核心删除测试及数据库事务测试 |
| 移动文件后旧路径移除、新路径建立 | 通过 | 实际 `rename` 临时目录测试 |

| 关闭后重新启动可恢复目录并应用期间变化 | 通过 | 本地目录配置恢复测试和重新打开数据库后的增量测试 |
| 不依赖网络、LLM 或云端服务 | 通过 | 当前实现与工作区检查 |

## 结果

M4 的核心行为、桌面生命周期和最终一致性场景达到当前定义的验收范围。M0–M4 第一阶段
产品基础完成；M5 语义搜索、云端同步和 Agent 系统仍未开始。

## 保留风险

- 操作系统 watcher 的具体事件顺序和资源上限依赖平台；事件丢失时采用完整重扫作为保守
  恢复路径。
- 当前只保存一个监听根目录，未来多目录需求需要单独的数据模型和交互设计。
- 真实用户规模下的长期运行、睡眠唤醒和极端权限环境仍需要后续现场使用观察；这不改变
  当前本地一致性边界。

## 结论

M4 验收通过，可以安全暂停在第一阶段完成状态；后续是否进入 M5 应由真实使用反馈和
产品决策另行确认。
