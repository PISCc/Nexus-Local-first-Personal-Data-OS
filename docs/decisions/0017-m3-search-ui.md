# ADR-0017：M3.4 搜索 UI 和桌面命令边界

- 状态：Accepted
- 日期：2026-09-01
- 范围：M3.4 搜索 UI

## 背景

M3.2 和 M3.3 已经在 `nexus-db` 中提供受限查询、元数据过滤、确定性 relevance 和
snippet，但用户还没有可操作的桌面入口。M3.4 需要把这些能力接入现有 Tauri/React
应用，同时保留 M1 手动重扫流程和本地优先边界。

## 决策

### 1. 搜索页作为现有桌面壳层的 Extension

新增独立 `SearchView` 组件，默认进入全文搜索；侧栏保留“文件索引”入口，用户可以回到
M1 手动重扫页面。现有启动状态、重扫命令、进度事件和测试选择器继续保留。

搜索界面沿用现有米灰画布、墨绿主色、琥珀错误色、方形边框和细线阴影，不引入新的视觉
系统、图标依赖或装饰性假数据。

### 2. 通过两个 Tauri 命令连接本地数据库

- `search_documents` 接收 `{ query, limit }`，在桌面层打开应用数据目录中的 SQLite，调用
  现有 `nexus_db::search_documents`，再转换为不包含完整正文的前端 DTO。
- `open_document` 接收 `documentId`，从 canonical `documents` 表解析原始路径，确认文件
  仍可访问后交给当前平台的系统打开/定位命令。

React 不直接访问 SQLite，也不拼接 SQL。每次显式提交查询时打开数据库，暂不引入持久连接、
共享锁或新的并发架构；搜索频率由“提交/Enter”控制。

### 3. 查询取消采用 UI 级 stale-response 防护

查询开始时记录递增 request ID。用户点击取消会立即结束当前 UI loading 状态并使后续返回
结果失效；已经提交给 SQLite 的同步工作不会被伪造为已中断。这样可以覆盖 M3.4 的取消
交互，同时把真正的数据库取消留给后续需要时再设计。

### 4. 所有显示内容作为文本处理

标题、路径、类型和 snippet 通过 React 文本节点渲染；snippet 的 `⟦命中⟧` 标记转换为
普通 `mark` 文本强调，不生成 HTML 字符串，不返回完整正文。后端错误映射为固定安全消息，
不展示路径、查询词或 SQLite 原始错误。

## 未采用的方案

- **输入即搜索或 debounce 查询**：会频繁打开数据库，且没有取消收益；M3.4 采用显式提交。
- **React 直接调用数据库**：破坏 UI/数据库边界。
- **引入 opener/search UI 依赖**：当前平台能力足够，不为一次打开动作增加第三方依赖。
- **持久数据库连接和后台查询线程**：属于并发架构变化，当前查询量和验收目标尚不足以证明必要。

## 风险和后续

- SQLite 查询仍可能因数据库锁或本地文件状态失败，界面显示安全错误并允许再次查询。
- UI 取消不停止已开始的 SQLite 调用；若后续真实查询耗时证明需要，再设计可取消数据库任务。
- 路径打开行为依赖操作系统；当前实现使用 Windows Explorer、macOS `open -R` 和 Linux
  `xdg-open`，不改变原始文件内容。
- 分页、GUI filter chips、搜索质量评估和增量索引不属于 M3.4。
