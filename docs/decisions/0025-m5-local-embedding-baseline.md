# ADR-0025：M5 本地 embedding 与混合检索基线

- 状态：Accepted（工程基线）
- 日期：2026-09-02
- 范围：M5.0–M5.4

## 背景

M4 已经把初始正文索引和文件变化后的增量更新连接起来。M3 的 SQLite FTS5/BM25 搜索是
当前可靠的确定性检索基础，但进入 M5 前，仓库没有已批准的本地模型文件、推理运行时或
向量存储方案。直接选择云端 API 会改变 Nexus 的默认隐私边界；直接加入大型推理依赖会
同时改变安装、发布和设备资源要求。

M5 本次先验证“向量生成 → 版本化保存 → 查询 → 混合排序 → 初始/增量维护”的完整工程
链路，不把一个临时实现描述成已经具备通用语言理解的产品能力。

## 决定

### 1. Provider 和数据范围

在 `nexus-core` 定义 `EmbeddingProvider` 边界。默认实现为确定性本地特征向量 provider：

- 模型 ID 为 `nexus-local-feature-hash`，版本为 `1`，维度为 `256`。
- 使用标题和正文，不使用来源路径、文件名、创建/修改时间或访问时间。
- 采用稳定的 signed hashing 和 Unicode 字符三元组特征，再做 L2 归一化。
- 不下载模型、不访问网络、不依赖第三方推理运行时。

该实现是管线基线，不是预训练语言模型；它不能证明不同词汇之间的同义关系，也不能作为
M6 问答的语言理解层。

### 2. 本地和隐私边界

所有向量生成、查询向量生成和向量存储均在本地完成。用户文件、路径、文件名、向量和
搜索历史不上传到服务。核心功能不依赖网络，provider 只接收调用方明确传入的文本，
不自行读取文件或访问外部服务。

### 3. 版本化 SQLite 存储

schema 5 增加 `embedding_models` 和 `document_embeddings`：

- 模型以 `(model_id, model_version)` 为身份，保存 provider 类型和维度。
- 向量以 `(document_id, model_id, model_version)` 为主键，另存标题/正文输入指纹。
- 模型身份已经登记后，provider 类型和维度不能静默改变；新算法使用新版本。
- 向量写入前校验文档存在、指纹长度、维度、有限数值和非零范数。
- 文档标题或正文更新、文档删除时由 SQLite trigger 清理旧向量。
- 读取到损坏向量时返回安全错误或跳过该候选，不让损坏数据静默影响搜索。

### 4. 混合检索

M3 的 lexical 搜索始终保留。查询中的正文关键词/短语进入 FTS5，同时由同一个本地
provider 生成查询向量；文件名、路径、扩展名、类型和日期过滤器同时约束 lexical 与
semantic 分支。

两路结果使用固定常数 60 的 Reciprocal Rank Fusion（RRF）合并，不直接把量纲不同的
BM25 分数和余弦相似度相加。结果以融合分数降序、文档 ID 二级排序，保证确定性。指定
模型不存在、没有可用向量或部分向量损坏时，保留可用 lexical 结果并安全降级。

### 5. 生命周期

完整索引使用稳定文档 ID 游标和有界批次建立向量；M4 的文件更新只刷新受影响路径，
并继续按同一批次上限写入可能对应同一来源的多个文档。删除和暂时无法解析的文件由
文档清理规则移除旧向量。任务支持取消，已经提交的批次保持有效，单个文件失败不终止
其他文件。

### 6. 评估与 reranking

复用 M3 固定的 10 条合成文档、9 个查询和人工相关性标注比较 BM25 与 hybrid。当前两者
Recall@3 均为 `0.9722`，Top-1 均为 `9/9`；hybrid 在当前小型 Debug 评估中有额外计算
开销。因此 M5 不加入 reranking，也不把当前结果外推为真实个人语料质量结论。

## 被否决或延期的方案

- **预训练本地模型**：需要先决定模型文件来源、许可、体积、推理运行时、CPU/内存预算、
  版本迁移和真实脱敏语料评估；本次延期，不静默选择依赖或下载模型。
- **云端或用户 API**：默认会改变本地优先和隐私边界；如果未来支持，必须是明确的可选功能，
  并单独记录授权、数据范围、失败和日志行为。
- **只保留向量搜索**：会损失 M3 已验证的可解释 lexical 搜索和过滤行为，因此不采用。
- **当前直接加入 reranking**：评估没有显示召回或 Top-1 改善，增加复杂度没有证据支持。

## 后果

正面结果是：无需新依赖或网络即可验证完整 M5 工程边界；模型身份、数据范围、回退行为和
增量维护都有明确测试。代价是：当前实现不具备真正预训练模型的通用语义能力，向量分支
仍需在更大规模上评估；将来选择真实模型时，需要新增模型适配、资源评估和迁移策略，且
必须保持 lexical 回退。

## 后续进入真实模型的门槛

只有在产品确认以下内容后，才进入真正的本地模型实现：模型来源与许可、安装和更新方式、
运行时支持的平台、资源上限、模型版本迁移、错误恢复、真实脱敏语料标注和质量目标。
