# ADR-0003：M1.1 流式文件扫描器

- 状态：已接受
- 日期：2026-09-01
- 范围：M1.1 递归遍历

## 背景

M1.0 已确定文件元数据模型，但还没有从文件系统产生记录的能力。M1.1 需要遍历
目录，同时面对权限异常、目录项变化、符号链接和大目录，不能因为单个路径失败
就终止整个扫描，也不能把所有路径一次性放入内存。

## 决定

1. 在 `nexus-core` 中提供实现 `Iterator` 的 `FileScanner`，每次只产出一个扫描结果。
2. 扫描结果分为 `File`、`Skipped` 和 `Failed`；失败结果携带路径和安全分类，迭代器继续处理后续路径。
3. `ScanOptions` 提供忽略路径和 `follow_symlinks`；默认不跟随符号链接。
4. 忽略路径按规范化后的路径及其子路径匹配，不访问被忽略目录。
5. 明确开启跟随符号链接时，使用已解析的目录身份去重，避免目录环路和重复遍历。
6. 扫描器只读取文件系统元数据，不读取文件正文，不写 SQLite，也不依赖 Tauri。
7. 根目录无法打开属于启动错误；根目录打开后出现的单项错误作为 `Failed` 结果继续返回。

## 取舍

- 使用显式迭代器比返回 `Vec` 更适合 10 万级文件，也让后续 M1.2 可以直接批量消费；
  代价是调用方需要自行统计结果。
- 允许显式跟随符号链接满足高级场景，但会增加目录身份解析和环路去重；默认关闭，
  普通扫描不承担这部分文件系统行为。
- 单项错误保留路径供上层统计或诊断，但错误文本不包含路径和原始系统错误，避免未来
  直接展示或记录时泄露用户信息。

## 后果

- M1.1 可以独立测试递归、忽略路径、符号链接和失败隔离。
- M1.2 可以在不修改扫描器的情况下消费 `ScanItem::File` 并批量写入数据库。
- 扫描统计、取消、后台任务和界面进度留给后续 M1.3/M1.4。
