# M4.2 事件归并与批量写入验收记录

## 验收范围

本记录验收重复文件事件的归并、最终路径状态判断、文件稳定性确认和增量数据库写入。
后台线程、应用关闭和重启恢复属于 M4.3–M4.4。

## 用户可理解的结果

连续保存同一个文件不会触发重复正文写入；重命名、删除和再次创建等事件顺序变化后，
索引以当前文件系统状态为准。文件正在写入或解析失败时，已有可用正文不会被半截内容
覆盖；数据库异常时，未完成批次不会留下半个文件操作。

## 验收检查

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 短时间重复创建/修改事件合并 | 通过 | `EventBatcher` 安静窗口测试 |
| 同一路径最终操作优先 | 通过 | 删除后创建顺序测试 |
| 重命名拆分为旧路径移除和新路径更新 | 通过 | 重命名归并测试 |
| 完整重扫信号覆盖局部事件 | 通过 | `RescanRequired` 归并测试 |
| 增量创建、更新、删除 | 通过 | 临时目录增量索引测试 |
| 重复事件不产生重复文档行 | 通过 | FTS/canonical 行数断言 |
| 损坏正文不覆盖既有正文 | 通过 | 解析失败保留旧文档测试 |
| 单批次数据库更新具备事务边界 | 通过 | `apply_file_mutations` 调用路径和 FTS 一致性测试 |

## 已执行验证

- `cargo fmt --all`
- `cargo test -p nexus-core`
- `cargo test -p nexus-db`

结果：`nexus-core` 62 项测试、`nexus-db` 28 项测试和 1 项搜索质量测试通过。

## 当前限制

- 事件归并器已经可用，但尚未由长期后台线程持有；M4.3 接入桌面生命周期。
- 单文件失败会保留旧状态并计入统计，后台任务如何展示和再次调度留给 M4.3。
- 应用关闭时的取消、事件停止接收和重启后的恢复尚未验收。

## 结论

M4.2 达到当前定义的归并、稳定性和事务写入范围，可以进入 M4.3 后台任务与关闭。
