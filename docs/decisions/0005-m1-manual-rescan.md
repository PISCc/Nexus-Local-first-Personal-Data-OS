# ADR 0005：M1.3 手动重扫闭环

- 状态：已接受
- 日期：2026-09-01
- 范围：`crates/nexus-core`、`crates/nexus-db`

## 背景

M1.1 已经提供逐项产出的文件扫描器，M1.2 已经提供有界批量 upsert，但两者还没有组成一次完整的重扫操作。手动重扫必须能够验证新增、更新和移除，同时不能因为扫描期间的单个失败或跳过而误删已有数据；后续 M1.4 还需要在扫描中途取消时保持数据库一致。

早期实现不应为了保存扫描状态增加持久化表或引入 watcher。重扫需要一个临时、可消费、可安全结束的数据库边界。

## 决策

### 1. 核心层提供一次性手动重扫入口

`nexus-core::rescan_directory` 接收数据库路径、扫描根目录、扫描选项和批次大小。它先启动扫描器，再打开本地数据库，逐项处理扫描结果，最后返回 `RescanSummary`。

根目录由上层传入，因此未来可以接目录选择器；M1.3 不在 Tauri 或前端实现选择器、后台任务和 UI 进度。

### 2. 使用连接级临时表记录扫描覆盖范围

`nexus-db::FileMetadataRescan` 在当前 SQLite 连接上创建三个临时表：

- `nexus_scan_seen`：记录本次成功写入的文件路径键。
- `nexus_scan_protected`：记录失败或跳过路径的范围。
- `nexus_scan_pending`：暂存本次成功读取的最新元数据。

临时表不会改变持久化 schema，扫描会话结束或被丢弃时清理。成功文件按配置批次写入 pending 表，并在同一事务中登记为已见路径；只有 `finish` 的最终事务才会把 pending 数据应用到持久化表。

### 3. 只清理已确认不存在的记录

扫描完成后，在选定根目录范围内删除同时满足以下条件的记录：

1. 本次扫描没有见到该路径。
2. 该路径不在失败路径或跳过路径及其子路径下。

因此，成功枚举的目录中已经消失的文件会被移除；读取失败的文件、权限失败的目录、忽略目录、符号链接和不支持的文件类型不会因为不完整结果而被误删。路径范围按平台路径键和目录边界判断，避免把 `library-old` 当成 `library` 的子目录。

### 4. 结束和取消保持一致

`finish` 在一个最终事务中应用所有暂存元数据并清理确认不存在的旧记录。扫描会话在 `finish` 前被丢弃时，临时表和暂存记录都会消失，持久化的 `file_metadata` 保持原状。因此上层可以在扫描每个安全检查点检查取消令牌，不需要回滚已经写入用户数据库的半成品。

### 5. 错误和统计分层

单个 `ScanItem::Failed` 进入失败统计并保护对应路径；单个 `ScanItem::Skipped` 进入跳过统计并保护对应路径。数据库连接、事务或清理失败仍返回 `RescanError::Persistence`，因为这不是单个文件问题。

`RescanSummary` 固定提供成功文件数、失败数、跳过路径数、移除记录数和已提交批次数，便于后续 UI 直接展示，不把统计逻辑放进界面组件。这里的批次是已提交到临时 pending 表的有界事务批次。

## 结果与取舍

- 不新增 schema 迁移，不持久化半成品扫描会话。
- 不需要把全部路径收集到调用方内存；已见路径和保护范围由 SQLite 临时表承载。
- 最终应用和清理共用一个事务；如果最终事务失败，持久化 upsert 和旧记录清理一起回滚，不会静默删除或伪造重扫成功。
- 如果调用方在 `finish` 前丢弃会话，所有 pending 批次都会随临时表清理，持久化的 `file_metadata` 保持不变。
- 没有新增第三方依赖，继续使用现有的 Rust 标准库和 `rusqlite + bundled`。

## 验证

- 首次重扫建立文件元数据记录。
- 第二次重扫验证文件更新、新增和已删除记录清理。
- 忽略路径保留原有记录。
- 相邻目录不会被选定根目录的清理逻辑误删。
- 零批次大小在打开扫描前返回错误。
- Unix 下符号链接目标消失时，失败链接记录保留，已确认消失的普通文件仍可移除。
