# ADR 0006：M1.4 可取消重扫、进度事件和桌面界面

- 状态：已接受
- 日期：2026-09-01
- 范围：`crates/nexus-core`、`crates/nexus-db`、`apps/desktop/src-tauri`、`apps/desktop/src`

## 背景

M1.3 已经能够由调用方同步执行一次完整手动重扫，但还没有桌面操作入口。扫描目录可能包含大量文件，不能占用界面线程；用户也需要知道任务是否仍在运行、已经处理了多少条记录，以及能否安全停止任务。

M1.3 的重扫会话已经把成功结果暂存在 SQLite 连接级临时表中。M1.4 需要沿用这一边界，确保取消不会把半成品写入持久化文件元数据表。

## 决策

### 1. Core 使用协作式取消和进度回调

`nexus-core` 提供可在线程之间共享的 `RescanControl`，内部使用原子取消标记。重扫在处理每个扫描结果前，以及准备最终提交前检查取消状态；收到取消后直接结束，不调用 `FileMetadataRescan::finish`。

重扫仍然通过 `RescanProgress` 回调报告已处理、成功、失败和跳过数量。Core 不依赖 Tauri，也不定义 UI 状态或事件名称。

### 2. Tauri 使用单活动任务管理器和后台线程

桌面壳层使用一个由 `Arc<Mutex<...>>` 保护的活动任务槽位，并为每次任务分配单调递增的 `scanId`。同一时间只允许一个手动重扫；重复启动返回固定的 `rescan_already_running` 错误，不排队、不覆盖已有任务。

`start_rescan` 只负责校验请求、准备应用数据目录、登记任务并启动后台线程；`cancel_rescan` 只接受当前活动任务的编号。后台线程结束后先清理活动槽位，再发送完成事件。

### 3. 使用两个稳定的 Tauri 事件契约

- `rescan-progress`：携带 `scanId`、`processed`、`filesSucceeded`、`filesFailed`、`pathsSkipped`。
- `rescan-finished`：携带 `scanId`、`status`、中文 `message`、可选 `summary` 和可选 `errorKind`。

字段通过 `camelCase` 序列化。完成状态固定为 `completed`、`cancelled` 或 `failed`。事件和 command 错误只暴露固定分类与非敏感说明，不携带完整用户路径、文件名、文件内容或原始系统错误。

### 4. 前端保留现有视觉系统并接入可观察工作区

React 页面增加全中文的文件索引工作区：用户输入完整扫描路径后启动重扫，页面显示任务状态、处理数量、成功/跳过/失败统计、完成后的移除记录与批次统计，并提供取消按钮。

前端对 command 返回值和事件 payload 做运行时校验，只接受当前 `scanId` 的进度和完成事件；旧任务或非法事件会被忽略。浏览器预览没有 Tauri 核心或事件总线时，页面仍可展示，但重扫操作只在桌面应用中可用。

本单元不新增原生目录选择器依赖，路径输入是可审阅的最小交互；是否引入目录选择器留给 M1.5 的最终验收和真实使用反馈。

### 5. 继续使用现有依赖

不引入异步运行时、Tauri 插件或第三方任务队列。Core 使用标准库原子类型和线程，前端使用已存在的 React、Tauri API 与测试工具。

## 结果与取舍

- 后台线程保证重扫不会阻塞界面；代价是任务状态需要通过明确的事件和活动槽位同步。
- 取消只在扫描结果边界生效，不强行中断正在进行的单个文件系统操作；这让资源释放和数据库边界保持简单可预测。
- 成功记录在 `finish` 前只存在于临时表，因此取消或线程异常退出不会把本轮半成品应用到持久化索引。
- 单活动任务策略暂不支持并行扫描或任务队列，但能避免多个重扫同时清理同一目录范围。
- 路径输入没有原生选择器的便利性，但不增加未经批准的依赖，也让浏览器预览和桌面命令契约保持一致。

## 验证

- Core 测试覆盖取消后持久化数据库保持不变，并保留 M1.3 的新增、更新、移除、失败保护、忽略路径和相邻目录边界测试。
- Tauri 壳层测试覆盖重复启动拒绝、只更新/清理匹配任务，以及共享取消控制器。
- React 测试覆盖文件索引工作区、启动请求、任务编号隔离的进度/完成事件和取消请求。
- 前端类型检查、Lint、格式检查、Rust 测试、Clippy、桌面检查和工作区构建作为交付验收。
