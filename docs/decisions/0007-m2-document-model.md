# ADR 0007：M2.0 最小 Document 模型

- 状态：已接受
- 日期：2026-09-01
- 范围：`crates/nexus-core`

## 背景

M1 已经建立本地文件元数据索引，但后续内容解析和全文搜索需要一个不依赖具体扩展名的统一文本结果。当前只进入 M2.0，目标是固定最小数据边界，不提前实现解析器、正文数据库或搜索接口。

## 决策

### 1. Document 保留五个最小字段

`Document` 包含：

- `id`：非空的 `DocumentId`，作为来源适配器提供的稳定 opaque 标识。
- `source`：当前只有 `DocumentSource::LocalFile`，保存绝对化后的本地路径。
- `title`：非空展示标题。
- `body`：统一文本正文，可以为空。
- `location`：当前提供可选的 1-based 起止行号，也可以表示整个文档。

模型字段不依赖 UI、Tauri 或 SQLite，后续搜索层可以直接消费它。

### 2. ID 生成不放进模型层

M2.0 只校验 ID 非空并原样保存，不擅自选择哈希、UUID 或数据库主键方案。来源适配器负责根据稳定来源身份生成 ID；这样不会把未来的存储策略提前固化，也避免引入新的依赖。

### 3. 本地文件路径只做绝对化

`DocumentSource::local_file` 复用现有路径规范化边界：空路径返回安全错误，相对路径转为绝对路径，不访问文件系统、不执行 `canonicalize`、不跟随符号链接。非 UTF-8 路径的无损身份问题仍由 M1 文件元数据层负责。

### 4. 模型错误使用固定安全分类

空 ID、空标题、无效来源路径和倒置/零起始行范围分别返回固定错误分类与中文用户说明。错误展示不包含用户路径、标题或正文；原始路径错误只保留在错误链中供进程内诊断。

### 5. M2.0 不实现解析行为

本单元不读取文件、不判断扩展名、不处理编码、不创建 parser crate、不新增第三方依赖，也不写入正文数据库。纯文本、Markdown 和代码的读取与解析留给 M2.1。

## 结果与取舍

- 模型足够表达后续文本解析的稳定输出，同时没有提前引入通用插件体系。
- opaque ID 延迟了具体稳定身份方案，但避免在没有真实持久化需求前锁定哈希或 UUID 依赖。
- 当前位置元数据只覆盖文本行范围；PDF 页码、HTML DOM 位置等格式专属信息留待对应解析单元决定。
- 正文允许为空，使元数据和内容抽取可以分阶段完成，但搜索层未来必须明确如何处理空正文。

## 验证

- 构造本地文件来源、稳定 ID、标题、正文和行范围成功。
- 相对来源路径被绝对化，空正文可以保留。
- 空 ID、空标题、空来源路径和无效行范围返回安全错误。
- `nexus-core` 不新增第三方依赖，模型测试与现有 Rust 工作区测试一起执行。
