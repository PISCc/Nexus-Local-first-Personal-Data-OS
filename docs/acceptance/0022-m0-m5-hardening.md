# M0–M5 巩固验收记录

- 日期：2026-09-02
- 状态：已完成
- 范围：M0 工程基础、M1 文件扫描、M2 内容解析、M3 全文搜索、M4 增量索引、M5 本地向量混合检索

## 验收结论

M0–M5 的现有能力已完成一次面向交付的巩固。重点不是增加新产品功能，而是把取消、失败、
异常数据和重复事件等边界重新验证，并修复初始正文索引可能留下半条记录的问题。

当前已确认：

- 初始正文索引按有界批次同时提交文件元数据、正文和全文索引；取消只丢弃未完成批次，
  不会留下正文与元数据不匹配的记录。
- 重扫确认文件已经消失时，旧正文和全文搜索命中会一起清理。
- M5 路径刷新会遵守配置的批次大小；任务一开始就取消时不会登记无效的模型状态。
- 查询中出现非法控制字符、数据库中的损坏向量或缺少向量时，搜索保持安全失败或回退到
  可用的全文搜索，不会让应用崩溃。
- M1 的 metadata-only 重扫、M4 的增量事务、文件变化归并和已有解析器边界保持通过。

## 关键行为边界

初始正文索引使用有界会话缓存保存待提交正文，每个批次把文件元数据、canonical 正文、FTS
一起写入事务；任务中止时未完成批次丢弃，已提交批次保持完整一致。这保持了 M1 metadata-only
API 的原有行为，同时避免 M3.6 产生孤立正文。

M5 的完整重建继续使用稳定文档 ID 游标；路径刷新现在按同一个批次配置逐批生成和写入向量。
向量查询遇到损坏记录时跳过该候选，仍返回 lexical 分支的可用结果。

- `cargo test --workspace --all-targets`

- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `pnpm format`
- `pnpm typecheck`
- `pnpm lint`
- `pnpm test`
- `pnpm build`
- `git diff --check`

额外的巩固定向测试覆盖：

- 初始正文索引取消只丢弃未完成批次，已提交批次的 metadata、canonical 正文和 FTS 保持一致
- 确认删除文件时清理旧正文
- 同一来源的多个文档按批次刷新 embedding
- 已取消的 embedding 任务不登记模型
- 损坏存储向量时回退 lexical
- 查询控制字符被拒绝

## 已知限制

- M5 默认 provider 仍是确定性的本地特征向量基线，不是预训练语言模型；这不改变 M0–M5
  的本地工程链路结论。
- 当前向量检索和质量评估仍需更大规模、真实脱敏语料继续测量；本次没有引入专用向量库、
  云端 API 或 M6 之后的能力。
- 初始正文索引的待提交内容受批次大小限制；每批提交后释放，未提交部分在取消时丢弃。
