# M4.3 后台监听任务与关闭验收记录

## 验收范围

本记录验收桌面层的后台监听生命周期、取消与关闭、增量任务状态展示，以及成功索引后
保存监听目录并在启动时恢复的行为。文件最终一致性的完整场景在 M4.4 单独验收。

## 用户可理解的结果

完成一次本地正文索引后，Nexus 会在后台关注该目录的变化；界面不需要持续等待文件事件。
应用关闭时会停止自动同步，未完成的批次不会留下半条数据库更新。重新启动时，Nexus 会
先重新整理已保存目录，再继续自动同步。

## 验收检查

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 监听等待和增量处理运行在独立后台线程 | 通过 | `WatchManager` 线程生命周期实现与桌面 crate 编译测试 |
| 同时只允许一个活动监听任务 | 通过 | 管理器活动槽位与安全错误分类 |
| 监听任务可取消并等待线程退出 | 通过 | 共享 `RescanControl`、关闭标记和 `stop` 测试 |
| 应用退出时先停止重扫，再停止监听 | 通过 | Tauri `RunEvent` 关闭处理 |
| 未完成批次不会绕过事务边界 | 通过 | 增量核心取消测试与数据库批次回滚测试 |
| 成功索引后保存监听目录 | 通过 | 本地配置读写测试 |
| 启动时根据已保存目录恢复索引和监听 | 通过 | 启动恢复路径与配置恢复测试 |
| UI 展示监听状态和增量摘要 | 通过 | React 监听事件测试；只接受经过运行时校验的 payload |
| 状态和错误不泄露文件内容或底层路径 | 通过 | 固定消息、错误分类和前端字段边界 |

## 当前限制

- 当前恢复策略是启动后对已保存目录做一次完整本地索引，不保存关闭期间的事件队列。
- 暂时只保存一个用户明确索引过的目录；多目录管理不属于 M4。
- 本单元没有引入系统托盘、后台常驻服务或云端通知。

M4.3 达到后台监听、取消、关闭和启动恢复的定义范围，可以进入 M4.4 最终一致性验收。
