# M4.0 文件变化判定验收记录

## 验收范围

本记录只验收“比较两次文件状态并识别需要重新处理的文件”。不包含实时文件监听、桌面自动更新、正文重新解析或数据库清理；这些属于 M4.1–M4.4。

## 用户可理解的结果

给定上一次和本次文件状态后，核心层能够稳定地区分：

- 新出现的文件；
- 大小或修改时间发生变化的文件；
- 大小和修改时间均明确相同的文件；
- 本次已经看不到的文件。

变化检测不会读取用户文件正文，也不会把路径写入错误消息。

## 验收检查

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 新增、修改、未变化、消失四类结果 | 通过 | `nexus-core` 变化分类测试 |
| 结果顺序稳定 | 通过 | 按路径排序测试 |
| 修改时间缺失时不误判为稳定 | 通过 | 保守修改测试 |
| 重复路径不被静默覆盖 | 通过 | 重复输入错误测试 |
| 空路径被拒绝 | 通过 | 输入校验测试 |
| 从现有文件元数据提取所需字段 | 通过 | `FileSnapshot::from_metadata` 测试 |
| 不引入新的外部依赖 | 通过 | 依赖清单与构建验证 |
| 不读取正文、不写数据库、不启动 watcher | 通过 | 模块边界审查 |

## 已执行验证

- `cargo fmt --all -- --check`
- `cargo test -p nexus-core`
- `cargo test --workspace`

结果：核心测试 46 项通过；workspace 测试全部通过。M4.0 只新增核心层变化判定，不改变数据库 schema、桌面命令或前端行为。

## 当前限制

- 需要监听的 CREATE、UPDATE、DELETE、MOVE/rename 尚未接入。
- 旧路径与新路径目前只能先表示为“消失 + 新增”，不能确认是同一文件移动。
- 变化判定当前不计算 hash；无法从大小和修改时间确认的更复杂竞态留给后续重检策略。

## 结论

M4.0 达到当前定义的验收范围，可以进入 M4.1 文件事件接入。
